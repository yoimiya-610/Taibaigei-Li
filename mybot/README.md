# 李太白给

耄耋是一只穿唐装、戴墨镜、提酒壶的群聊猫诗人，基于 NoneBot2 与 OneBot v11。当前产品版本为 v0.9.0。

## 普通对话

在消息句首、句中或句尾真实 @李太白给 都可发起对话。从他人消息复制粘贴后变成普通文字的 `@李太白给` 也可使用，例如 `你好 @李太白给 聊聊今天的趣事`；文字唤醒词与后文之间需有空格、换行或标点，兼容 QQ 的特殊空格与全角 `＠`。单独呼唤会收到空消息提示，`@李太白给 清除记忆` 可重置本次会话。

私聊、回复机器人消息与已配置的昵称呼唤沿用既有方式。送礼、墨赞等功能中的群友目标仍需真实 @ 消息段，复制的昵称文字不会被当成目标账号。

## 启动

在包含 `mybot/` 的发布目录根目录执行：

```powershell
uv sync --project mybot --locked
uv run --project mybot li-taibaigei
```

也可用标准模块入口启动：

```powershell
uv run --project mybot python -m mybot.main
```

首次运行前，将 `mybot/.env.example` 复制为 `mybot/.env`，填入自己的 API Key、连接配置、管理员 QQ 号和群号。`DAILY_GREET_GROUPS` 留空时不会发送定时早晚安问候。运行数据会保存在 `mybot/data/`，备份会保存在根目录 `backups/`；这些运行产物均不应提交到 Git。

两个无参数入口都会先运行结构化配置预检；`error` 会在 NoneBot 初始化、业务插件加载和端口绑定前以退出码 `78` 结束，`warning` 不阻止启动。预检不执行 OneBot 网络探测，也不输出任何配置值或完整绝对路径。完整检查项与修复方式见 [配置参考](../docs/configuration.md)。

OneBot 连接建立后才会执行 `get_version_info` 与 `get_status` 只读能力探测。系统管理员可使用 `/系统诊断` 查看连接、实现版本和名片点赞、群戳一戳、精华消息、图片地址刷新、图片 OCR 的脱敏摘要；扩展能力缺失只影响对应功能，不影响机器人整体启动。无法识别实现时按标准 OneBot 能力运行，扩展能力保持 `unknown`，待真实业务调用结果更新。

### OneBot 最低能力与可选增强

- 最低能力：OneBot V11 标准的 `send_like` 与 `get_image`，分别用于名片点赞和图片地址刷新。
- 可选增强：`group_poke`、`get_essence_msg_list`、`set_essence_msg`、`delete_essence_msg` 与 `ocr_image`；NapCat 可按实现声明登记，普通或无法识别的 OneBot 实现不会被误判为 NapCat。
- 状态含义：`supported` 表示已有标准、实现声明或真实成功调用依据；`unsupported` 表示实现明确不支持；`unknown` 表示尚无无副作用依据；`degraded` 表示连接、探测或最近一次对应业务调用异常。

能力探测禁止发送消息、点赞、戳一戳或修改精华与群设置。有副作用的扩展接口只在真实业务调用发生后更新对应状态。断线会把已知可用能力记为 `degraded`，重连后重新执行只读探测。

历史小游戏源码会随发布包保留，但默认关闭。QQ群主与群管理员身份不会自动获得机器人管理权限；群聊权限由系统管理员按群授权，系统级功能仅由系统管理员管理。

## 可观测性与日志

应用日志统一写入 `mybot/logs/bot.log`，按天轮换并保留 30 天。每次已匹配命令都会记录独立业务编号、命令名、处理模块、完成状态和毫秒耗时；命令处理期间的插件日志会自动带上同一业务编号、事件类型及群、用户上下文，便于串联一次请求的账务、平台调用与异常记录。

日志不会在命令生命周期记录中保存命令参数或消息正文。QQ 用户号、群号和目标号只保留首尾片段；API Key、Authorization、token、secret、password、cookie 等字段会替换为 `<redacted>`。示例格式如下：

```text
[2026-07-16 20:30:00] [plugin.observability] [INFO] [business_id=TB-20260716123000-a1b2c3d4] [event=message command=/积分 group_id=123****890 user_id=987****210] command_completed status=ok duration_ms=12.34 handler=points exception=-
```

## 群聊日志与备份保留

v0.4.3 起可通过 `mybot/.env` 配置显式保留策略。所有数值默认都是 `0`，表示不自动清理；升级后不会删除任何既有日志或备份。

| 配置 | 默认值 | 说明 |
| --- | ---: | --- |
| `GROUP_CHAT_LOG_RETENTION_DAYS` | `0` | 正整数时清理超过该天数的合法历史群聊日志；当天文件始终保留 |
| `BACKUP_KEEP_DAYS` | `0` | 正整数时按生成时间保留部署备份 |
| `BACKUP_KEEP_COUNT` | `0` | 正整数时至少保留最新的指定数量部署备份 |
| `BACKUP_INCLUDE_GROUP_CHAT_LOGS` | `true` | `false` 时只从备份中排除 `data/group_chat_logs/`，其他运行数据仍会打包 |
| `BACKUP_INCLUDE_IMAGE_LIBRARY` | `false` | `true` 时将 `data/image_library/` 的图片原文件与索引纳入每日备份 |

天数与数量同时启用时采用保守交集：一个备份只有在既超过天数、又位于最新保留数量之外时才会删除。负数、非数字、超过 36500 天或超过 100000 份的值，以及非法布尔值都会记录诊断并停用本轮清理。推荐先从日志 30 天、备份 14 天且至少 7 份开始，再按群活跃度和磁盘容量调整；保留天数越长、备份包含的群聊正文越多，磁盘占用越大。

任何正式操作前先预览：

```powershell
uv run --project mybot python -m mybot.common.retention --dry-run
```

预览只输出候选数量、日期范围和预计空间，不展示 QQ 号、昵称或消息正文，也不会修改文件。人工确认后才可显式执行：

```powershell
uv run --project mybot python -m mybot.common.retention --apply
```

`--apply` 会先在 `backups/` 写入临时包，确认压缩包可重新打开、生成并复核 `.sha256` 清单，再原子发布正式备份并执行清理。每日计划任务也只会在本次新备份通过验证后清理；配置为 `0` 时只保持原有每日备份行为。备份日志已接入 `mybot/logs/bot.log` 的 30 天轮换，不再向 `backups/backup.log` 追加。

恢复前应停止机器人，先用 `Get-FileHash -Algorithm SHA256 <备份文件>` 与同名 `.sha256` 第一列比对，再用 `tar -tzf <备份文件>` 验证成员列表。建议先解压到新的临时目录，核对所需的 `data/` 文件后再恢复，避免覆盖仍在变化的运行数据。若要停用策略，将三个保留数值恢复为 `0`，再次 dry-run 确认没有候选后再回滚代码；代码回滚无法恢复已经删除的日志或备份，`BACKUP_INCLUDE_GROUP_CHAT_LOGS=false` 生成的包也无法恢复被排除的群聊正文。

## 群聊权限

系统管理员可使用 `/管理员 群号 QQ号 权限等级` 授予 1 至 5 级群聊权限，使用等级 `0` 撤权，省略权限等级可查询。授权只对指定群生效，并保存于 `mybot/data/admin_permissions.json`。

- 1 级：只读查看当前群的公开功能状态。
- 2 级：管理诗词、趣味、情感、谜语、翻译和实用工具等低风险内容功能。
- 3 级：管理 AI 对话、签到积分、礼物社交、语录、每日问候、月榜和酒馆等常规群配置。
- 4 级：管理六个历史积分概率游戏，并维护本群黑名单。
- 5 级：管理本群黑名单模块、频率限制和群聊记录等高影响群功能。

五级权限逐级包含前级能力，但 5 级仍不是系统管理员，不能跨群授权、管理系统黑名单、执行 debug 或改动全局功能。

## 系统管理员专用命令

系统管理员只由环境变量 `BOT_ADMINS` 或 `SUPERUSERS` 配置。聊天命令不能新增、删除、覆盖或降级系统管理员。以下命令不会出现在机器人普通帮助或功能列表提示中：

系统管理员使用 `/功能列表 [群号]` 时仍可查看完整功能清单；可在群聊或私聊末尾附加群号，查看并调整指定群的群级状态。普通群聊管理员不能附加群号，仍只可管理当前群。

- `/管理员 群号 QQ号 [权限等级]`：查询、授予或撤销指定群的机器人管理权限。
- `/功能列表 [群号]`：查看当前群或指定群的完整功能状态。
- `/开启功能 功能名 [群号]`、`/关闭功能 功能名 [群号]`：调整当前群或指定群的功能状态。
- `/全局开启功能 功能名`：统一开启目标功能，并清除该功能已有的群级覆盖。
- `/全局关闭功能 功能名`：统一关闭目标功能，并清除该功能已有的群级覆盖。
- `/全局开启功能 群聊记录`、`/全局关闭功能 群聊记录`：统一控制所有群的群聊记录收录。
- `/系统诊断`：只读查看存储、计划任务、付费回合、插件、备份与管理员审计摘要；`/系统诊断 清单` 展示全部数据路径及 schema 版本。
- `/系统黑名单`、`/系统黑名单 内容`：查看系统违禁词，或添入、移出一项。
- `/debug 1`：切换机器人全局应答状态。
- `/debug 2 @某人 数字 [群号]`：在当前群或指定群为目标用户增加积分。
- `/debug 3 @某人 数字 [群号]`：在当前群或指定群为目标用户增加魅力。
- `/debug 4 [群号]`：省略群号时统一切换六个历史小游戏，附加群号时只切换指定群。
- `/debug 运势 [群号]`：查看当前群或指定群的运势调试信息。

四级及以上群聊管理员与系统管理员可在对应群中使用 `/黑名单` 查看本群黑名单，或使用 `/黑名单 内容` 添入、移出一项。各群条目相互隔离。

## 插件元信息

每个 `mybot/plugins/` 与 `mybot/plugins_disabled/` 下的插件都必须通过 `PLUGIN_META = declare_plugin(...)` 声明功能元信息，包括功能键、名称、默认开关、群级或系统级管理范围、权限等级、运行数据路径、隐私等级与备份策略。`HELP_ITEMS`、`COMMAND_ALIASES` 和可选的 `PUBLIC_COMMANDS` 仍放在对应插件内，避免公共层反向依赖插件实现。

新增或调整插件后应同步维护这些声明。`mybot/tests/test_plugin_metadata.py` 会加载全部插件，检查声明完整性、功能键唯一性、权限范围、数据路径、隐私与备份字段，以及帮助项和命令别名的基本契约。功能名称、默认状态和权限等级应只在 `PLUGIN_META` 中修改，不要重新向 `common/feature_flags.py` 或 `common/admin.py` 添加平行映射。

## 数据健康、透明与审计

v0.6.1 起，`mybot/common/data_health.py` 维护版本化运行数据清单。清单覆盖标准 JSON 文件、按群保存的 YAML 日志目录与图片库目录；每项都声明当前代码支持的 schema 版本。启动巡检只读取文件结构、编码、schema、任务注册、未完成付费回合与备份摘要，缺失文件视为功能尚未产生数据，不会自动创建。发现损坏或超前 schema 时只记录提示，不会尝试修复或用默认空数据覆盖原文件。

v0.6.3 起，`mybot/common/usage_policy.py` 统一维护历史小游戏、图片库与 AI 请求的用户、群、功能三级滚动配额，并把单次付费工作接入既有幂等账务与 `paid_rounds.json`。付费请求先封存积分，结果完成后再结算；重复请求会识别处理中状态，重启后有完成标记的操作继续结算、没有结果的操作安全退款。持久化记录只保留请求与结果摘要，不保存用户原文或模型正文。

群友可在群内使用 `/本群数据` 查看本群哪些收录功能已开启，以及群聊日志天数、图片容量和两类可选备份策略。该命令不读取或展示 QQ 号、昵称、消息正文、积分、选票、图片清单等成员明细；关闭功能只停止新增，历史记录仍原位保留。

系统管理员可使用 `/系统诊断` 查看存储、计划任务、付费回合恢复、插件元信息、备份校验与审计摘要；使用 `/系统诊断 清单` 查看全部相对路径和 schema 版本。正常诊断为只读操作，只有实际执行管理员功能开关、群授权、debug 变更或跨群操作时才会向 `mybot/data/admin_audit.json` 追加审计记录。审计最多保留最近 10000 条，轮替数量单独累计；记录不包含消息正文或密钥。
